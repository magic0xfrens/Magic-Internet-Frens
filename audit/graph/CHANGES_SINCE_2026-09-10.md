# CHANGES SINCE 2026-09-10 -- new skeleton vs. the previously committed graphs

Generated by `diff.py <new skeleton> <old graph>`. Nodes are keyed by
`(contract, name, signature)`.

## Read this header before reading the counts

**The old graphs predate `body_sha1`.** They therefore cannot report CHANGED:
a function whose body was rewritten in place, at the same line and with the same
signature, is INVISIBLE to these three diffs. Only ADDED, REMOVED and MOVED are
meaningful below. Every diff taken from this build forward has body_sha1 on both
sides and reports CHANGED properly.

Two further legacy-schema adjustments are applied so that formatting is not
reported as churn:

1. Old graphs carry no `name` field, so the name is re-derived from the signature.
2. `perp.json` and `hook.json` omit the leading `function `/`modifier ` keyword from
   the signature, and all three old graphs hand-collapse multi-line parameter lists.
   The diff key normalizes both away.

Cluster membership also changed between builds (`PerpStakerOracle.sol` is now in
`perp`; `vendor/BaseHook.sol` and `vendor/HookMiner.sol` and `cauldron/LegacyBuyLib.sol`
are now in `hook`; `CauldronRegistry` nodes are no longer in `rotation`), so some
ADDED/REMOVED entries are re-clustering rather than code churn.
