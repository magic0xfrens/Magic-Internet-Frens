## Verdict (≤200 words)

Sections C and E-D are now more coherent in the contracts than in either the spec or
the docs that describe them: the two headline gaps the spine spec raised (`E_D:71-125`
post-rotation pinning, `C:184` asymmetric `isDead`) are closed in code, and the spec
still asserts them. Nothing here can make a user sign a losing transaction — the
rotation panel simulates before signing, and every death/perp gate refuses rather
than mispricing. The real debt is observational. Three surfaces landed today with no
consumer: `QueueInsolvent`, `NotArmed` and `TokYieldForfeited` are invisible to a
frontend that maps errors by hand, and `PartiallyClosed`/`TokenDebtWrittenOff` are
invisible to an indexer whose PerpEngine ABI predates the death band that makes
partial fills routine. The one economic incentive that breaks first is not the death
band or the keep-alive cost: it is the perp engine parking itself as "dead" after a
rotation that one wei of quote stake stopped from syncing, because the un-stranding
path is a timelock call and the UI tells the user the token died. Fix the error maps
and the PerpEngine event list before the docs.
